# References and provenance

- OpenWrt integration reference: [nikkinikki-org/OpenWrt-nikki](https://github.com/nikkinikki-org/OpenWrt-nikki), inspected at commit `78e1a751d55ed0762811f054ee699049473da7b8` (retrieved 2026-10-19). Nikki is distributed under GPL-3.0. FII independently implements its own configuration model and service code, using Nikki's procd lifecycle, profile validation and firewall recovery approach as references. Router settings additionally reference `view/nikki/proxy.js` and `ucode/hijack.ut` for independent LAN/router scope, interface discovery, device/UID access control, and OUTPUT-to-loopback TPROXY routing. FII does not bundle Nikki's configuration-management UI or firewall generator.
- Configuration-management reference: local `E:\github\sub-converter-flutter`, particularly `lib/domain/output_repository.dart`, `lib/domain/mihomo_yaml_service.dart`, `lib/domain/models.dart`, `lib/data/database/tables.dart` and `lib/data/backup/app_backup_service.dart`. Source/override/output composition, quota semantics, ID order and YAML merge operators were checked against current source.
- Mihomo: [MetaCubeX/mihomo](https://github.com/MetaCubeX/mihomo). Application IPKs contain no Mihomo binary and have no dependency on a Mihomo package. After installation, the LuCI core manager downloads the unmodified `amd64-compatible` Linux x86_64 asset from either the latest official Release or [Prerelease-Alpha](https://github.com/MetaCubeX/mihomo/releases/tag/Prerelease-Alpha). The core is GPL-3.0 licensed; source for stable releases is available from the corresponding tag in the upstream repository, and Alpha assets identify their build commit.
- Linux core compressed-asset SHA-256: `ba3ce607747a07f948fc35780e108a4a7c7f552a38b9bd4d115f313ebcb89c20`.
- Windows verification-core ZIP SHA-256: `974a4d7ad69aed27aa2e8f91d61113573c14dadb14562c63e58effabf59816f0`. This binary is used only for local checks and is not part of the OpenWrt packages.
- The fixed hashes above refer to developer verification assets, not bundled application payloads. `tools/fetch_core.py` obtains local verification binaries; `tools/verify_core_downloads.py` checks both live channels. The router's core manager verifies the current official GitHub release-asset digest before installing a core. `tools/build_ipk.py` builds application packages only.
